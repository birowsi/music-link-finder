# 검색 판정 규칙

웹과 Windows 앱은 `src/search.rs`를 공유한다. 이 문서는 검색 품질을 수정할 때 지켜야 할 동작 기준이며, 고정 회귀 사례는 `tests/fixtures/search-policy.json`에서 관리한다.

## 1. 곡명 일치와 관련 추천

- 곡명 일치는 제목에 **완전한 곡명 또는 등록된 전체 별칭**이 있을 때 인정한다. 아티스트명, 작품명, 별칭의 일부 단어만으로 일치시키지 않는다.
- 비교 전에 NFKC 정규화와 소문자 변환을 한다. 문장부호와 띄어쓰기 차이는 허용하지만, 다른 단어 안의 부분 문자열은 일치시키지 않는다. 예: `작은 사랑의 노래`와 `작은사랑의노래`는 일치하고, `작은 사랑의 다른 노래`는 일치하지 않는다. `봄`과 `봄날`, `love`와 `clover`도 구분한다.
- 별칭 확장에도 같은 이름 경계를 적용한다. 긴 단어 안에 `키미노마치마데`나 `토키메키 포포롱` 일부가 들어 있다고 다른 곡으로 검색어를 바꾸지 않는다.
- 미등록 입력은 `official`, `한글 발음`, `노래방` 같은 검색 수식어를 제거한 나머지를 하나의 전체 이름으로 취급한다. 임의로 번역하거나 원제·가수를 추측하지 않는다. 미등록 아티스트를 곡명 앞뒤에 붙이거나 이름의 단어 순서를 바꾸면 일치하지 않을 수 있다.
- 등록된 곡은 전체 별칭으로 식별할 수 있다. 작품명으로 찾는 경우에는 전체 작품명과 요청한 OP/ED·기수의 명시적인 일치가 모두 필요하다. 예: `주문토끼 2기 OP` 검색에서 작품명만 있거나 `2기`가 빠진 영상은 곡명 일치가 아니다. 등록된 해당 곡명 `No Poi` 자체가 있으면 제목에 OP/기수를 반복해서 적지 않아도 된다.
- 요청과 반대인 OP/ED 또는 다른 기수가 제목에 명시되면 전체 곡명이 있어도 곡명 일치에서 제외한다. OP와 ED를 함께 적거나 여러 기수를 함께 적은 모음 영상도 해당한다. 같은 작품이라는 근거가 있으면 관련 추천에는 남을 수 있다.
- OP/ED와 기수의 충돌 판정은 미등록 작품 검색에도 적용한다. 기수 표기는 `2기`, `제 2 기`, `시즌 2`, `season 2`, `S2`, `2nd season`을 지원한다. 기수 없는 제목을 다른 기수라고 추정하지 않는다.
- 관련 추천은 **등록된 전체 아티스트명·별명 또는 전체 작품명**이 영상 제목이나 채널명에 있을 때만 인정한다. 작품·기수를 명시한 미등록 검색에서는 입력의 전체 작품명을 문맥으로 쓴다. 제목과 채널의 일부 단어를 이어 붙여 아티스트를 만들어내지 않는다.
- 미등록 일반 곡은 공통 단어만으로 다른 곡을 추천하지 않는다. 관련성이 부족하면 추천 수를 채우지 않는다. 채널명은 곡명 일치 근거로 사용하지 않는다.

현재 별칭 확장 대상은 `키미노마치마데`, `두근어질`, `잇떼/잇테`, `DSCF`, `토키메키 포포롱`, `주문토끼 2기 OP/ED` 계열이다. 별칭 데이터는 코드에 등록돼 있으며, 범용 곡 데이터베이스나 자동 가수 식별 기능은 없다.

## 2. 발음과 자막의 구분

영상 유형은 **제목에 적힌 단서**로 분류한다. 영상 화면·음성·실제 자막 트랙을 검사하거나 내용의 정확성을 보장하지 않는다.

| `kind` | 조건 | 기본 표시 |
| --- | --- | --- |
| `pronunciation` | 발음 모드에서 `한글발음`, `한글 발음`, `한국어 발음`, `발음가사`, `독음` 등 발음 단서가 있음 | 한글 발음 |
| `subtitle` | 발음 단서는 없고 `한글자막`, `한국어 자막`, `자체 자막` 등 자막 단서가 있음 | 자막 |
| `karaoke` | 노래방 모드에서 `karaoke`, `카라오케`, `노래방`, `반주`, `MR` 단서가 있음 | 노래방 반주 |
| `general` | 조건에 맞는 곡을 찾지 못해 제공하는 원문 일반 검색 결과 | 일반 결과 |

- 발음과 자막 단서가 모두 있으면 `pronunciation`으로 분류한다.
- OP/ED·주제가·가사라는 표현만으로 발음 또는 자막 영상으로 인정하지 않는다. 별칭 확장 여부와 관계없이 같은 기준을 적용한다.
- 자막 영상은 발음 영상 뒤의 보조 후보다. 노래방 모드에서는 발음·자막 단서만 있는 영상을 반주 결과로 취급하지 않는다.
- 관련 추천 여부와 영상 유형은 별개다. 자막 추천은 `관련 추천 · 자막`으로 표시한다.
- 영문 단서는 단어 경계를 확인한다. `Believe`의 `live`, `unofficial`의 `official`, `Mr.Children`의 `MR`을 잘못 해석하지 않는다.

## 3. 일반 검색으로 보완하는 조건

곡명이 일치하고 요청한 유형까지 충족하는 결과가 하나라도 있으면 해당 결과와 보조 자막, 관련 추천을 제공한다. 발음 모드의 자막 영상이나 다른 곡 추천만으로 일반 검색을 막지 않는다.

요청 유형의 곡명 일치 결과가 없으면 다음 순서로 표시한다.

1. 사용자가 입력한 원문에 대한 일반 YouTube 결과 최대 8개.
2. 곡명이 일치하는 보조 자막 결과.
3. 관련 추천.

일반 결과는 유형·곡명·OP/ED·기수 일치를 보장하지 않으며 `일반 결과`로 명확히 표시한다. YouTube에서 가져온 결과의 상대 순서를 유지한다. 이미 식별된 보조 자막과 URL이 겹치면 일반 목록에서 제외하고 자막으로 한 번만 표시한다. 다른 중복 URL도 제거한다.

일반 검색이 비어 있거나 실패해도 확보한 자막·관련 추천은 유지한다. 전체 검색 요청에서 후보를 하나도 얻지 못하면 오류를 반환한다. 일부 요청 실패는 나머지 결과를 막지 않는다.

웹과 Windows 앱은 **화면 맨 위 결과를 선택하고 자동 복사**한다. 일반 결과가 먼저 제공되는 경우에도 순서를 다시 바꾸지 않는다.

## 4. 결과 정렬과 개수

일반 검색 대체를 제외한 후보는 다음 우선순위로 정렬한다. 아래쪽 조건의 가점이 위쪽 조건을 뒤집지 못한다.

1. 곡명 일치가 관련 추천보다 먼저.
2. 발음 모드에서는 발음 표기 영상이 자막 영상보다 먼저.
3. 커버·라이브·공연·악기 연주 등 수행 단서가 없는 영상이 먼저.
4. 발음 모드에서는 제목의 `official`, `original`, `공식`, `公式` 단서가 있는 영상이 먼저. 노래방 모드에서는 제목·채널의 KY/TJ/금영/태진/Kara-U 단서가 있는 영상이 먼저.
5. 앞선 조건이 같으면 세 검색 결과를 순위별로 번갈아 합친 순서가 먼저. URL이 겹치면 먼저 나온 항목을 유지한다.

`instrumental`은 발음 모드에서는 연주 단서로 취급하지만 노래방 모드에서는 정상 반주 표현이므로 감점하지 않는다. 가수 이름·`feat.` 또는 검색 결과에서 반복되는 단어만으로 공식·원곡이라고 추정하지 않는다.

곡명 일치와 보조 자막을 합쳐 최대 8개, 추천은 최대 12개다. 일반 검색으로 보완한 경우에도 최종 결과는 최대 20개로 제한하므로 뒤쪽 추천 수가 줄어들 수 있다.

`score`는 신뢰도나 확률이 아니라 정렬 키다. 구현은 곡명 일치 100,000, 요청 유형 충족 10,000, 수행 단서 없음 1,000, 우선 출처 100, 병합 순서 0~99의 구간을 사용한다. 순서 점수는 100번째 이후 0이며 동점에서는 원래 순서를 유지한다. 일반 결과는 재정렬하지 않고 `score: 0`을 사용한다.

## 검색 요청과 검증

- 모드별 검색어 3개와 원문 검색어 1개를 동시에 요청한다. 원문 검색은 일반 결과 보완에 사용한다.
- YouTube 검색 HTML의 `ytInitialData`에서 영상 제목·채널·영상 ID를 추출한다. API 키를 사용하지 않는다.
- 각 요청의 제한 시간은 25초다. `search_youtube`의 `limit`는 **검색 요청 하나당 가져올 후보 수**이며 최종 표시 개수가 아니다. 웹은 25개, Windows 앱은 30개를 요청한다.
- 고정 사례는 전체 곡명, 다른 곡·아티스트, 다른 OP/ED·기수, 자막만 있는 경우, 일반 결과 중복, 정렬 우선순위와 한 글자 곡명을 검증한다. 네트워크 테스트는 YouTube 접근과 파싱을 점검하는 보조 검사이며 결과 순위는 변할 수 있다.

```powershell
cargo fmt --all -- --check
cargo test --offline --features windows-app --lib --bins
node --test tests/web-results.test.cjs
# 실제 YouTube 응답을 사용하는 선택 검사:
cargo test --lib search::tests::live_ -- --ignored --nocapture
```

`tests/web-results.test.cjs`는 브라우저 DOM을 대신하는 작은 테스트 환경에서 실제 `web/app.js`를 실행한다. 일반/자막/추천의 표시 순서, 자막 표시, 첫 선택과 자동 복사, 늦은 응답 무시를 검증한다. 빈 검색어로 다시 제출하면 진행 중 검색을 취소하고 이전 결과를 표시·자동 복사하지 않는지도 확인한다. Windows 입력 테스트는 검색창의 위아래·좌우 여백을 눌러도 입력 포커스가 잡히는지 검증한다. 실제 브라우저와 Windows 앱의 화면 배치는 별도 시각 검토 대상이다.
